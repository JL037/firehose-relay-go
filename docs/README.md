# docs

The project's working record. Three kinds of document, one directory each:

| Directory              | What lives here                                                        |
| ---------------------- | --------------------------------------------------------------------- |
| [`planning/`](planning/) | Plans and design decisions *before* the work — the roadmap, the why.  |
| [`worklogs/`](worklogs/) | Execution logs — what actually got done, dated, as it happened.       |
| [`lessons/`](lessons/)   | Errors hit and lessons learned — so the same wall isn't hit twice.    |

## Conventions

- One Markdown file per entry, named `YYYY-MM-DD-short-slug.md`.
- Newest entries are easy to find by date; each folder's README explains its
  own template.
- Keep entries short and honest. A worklog that records what *didn't* work is
  more useful than one that only lists wins.
